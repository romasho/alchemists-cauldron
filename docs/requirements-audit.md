# Requirements audit

Source: [RS School assignment](https://github.com/rolling-scopes-school/qualifying-stage/blob/main/tasks/game-alchemists-cauldron/README.md), including the linked Level 2 and Level 3 stories. Checked on 24 October 2026.

| Requirement                                                               | Local implementation and evidence                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Level 1 game, stock, recipes, bars, timestamp timer, lives, pause, Top-10 | Existing rules retained; pure rule tests and browser gameplay checks                                                                                                                                                                                                                |
| US 2.1: difficulty                                                        | One typed table; Easy 4/4/180s/5 lives/±12/100/+15s, Medium 6/4/150s/3/±8/200/+10s, Hard 8/5/150s/3/±5/300/+5s. Recipes and stock use the selected difficulty. Difficulty cannot change during a live run.                                                                          |
| Difficulty leaderboards                                                   | Separate storage buckets; Difficulty column. Original Medium entries retain their original key.                                                                                                                                                                                     |
| US 2.2: save/continue                                                     | Meaningful transitions and remaining seconds are saved; page hiding pauses and saves. Continue restores paused with original stock/recipe/mixture. Validation handles corrupt data; exit and finish clear the save.                                                                 |
| US 3.1: HTML5 drag-and-drop                                               | Native dragstart/dragover/dragleave/drop, highlighted cauldron, shared click/drop action and stock/capacity/status guards. A real mouse drag changed stock 9→8 and counter 0→1 in the browser.                                                                                      |
| US 3.2: tooltip                                                           | No base-stat values on cards. Desktop hover/focus shows signed values. Fixed-position tooltips choose left/up near edges, avoid scroll clipping, and hide on pause. Mobile has an explicit details button.                                                                          |
| Empty stock                                                               | Slot remains in place; icon hidden, dimmed, stock 0. Add control disabled and not draggable or keyboard-focusable; details button hidden.                                                                                                                                           |
| US 3.3: reactions                                                         | All 15 definitions are typed. Easy enables none, Medium Bubbling + Solar Frost, Hard those plus Volatile Mix. Current values are always recomputed from the mixture; time/life effects fire only when entering an active combination. Tests cover repeated activation and clearing. |
| US 3.4: Pour Out                                                          | Clears mixture, spends 10 seconds, does not return stock or lose a life; disabled for empty mixture.                                                                                                                                                                                |
| US 3.5: effects                                                           | CSS success, explosion and screen shake, floating ingredient images and smooth markers. Animation-end events clean up reaction presentation; no decorative timers. Reduced motion is respected.                                                                                     |
| US 3.6: shortcuts                                                         | 1–8 add, B brews, O pours, P pauses; native Enter/Escape resumes the focused pause flow. Handler is gated by status, dialog and text input; browser shortcuts are preserved.                                                                                                        |
| Background                                                                | Background is on body with cover/fixed, filling the whole viewport. Control reading width does not limit the backdrop.                                                                                                                                                              |
| Adaptive layout                                                           | 375–1920 px; short screens keep actions outside the scroll area. Twelve recorded cases include all difficulties, long recipes, full cauldrons and depleted stock. See layout-audit.json.                                                                                            |
| Technical constraints                                                     | TypeScript game code, native browser APIs, no runtime framework/library, no any; data/rules/state/storage/rendering separated. Individual assets instead of a composite interface image.                                                                                            |

## Verification limits

Browser interaction checks used the available desktop browser, including mobile-size viewports. Actual touch hardware was not tested; touch dragging is optional in US 3.1 and click/tap remains available. Tests do not submit leaderboard scores or clear existing records. Preview fixtures disable autosave and do not modify the user's unfinished game.

The repository/RS App delivery workflow is separate: no push, new remote PR, deployment or course submission was performed as part of these local changes. The existing public deployment may lag behind the workspace.
